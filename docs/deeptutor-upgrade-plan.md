# DeepTutor 参考视频：工作台升级方案

## 目标与依据

参考文件：用户提供的 `DeepTutor.mp4`。
读取到的规格为 1920×1080、30 fps、约 29.37 秒。分析依据是每秒抽帧、6.8 秒高清帧及约 3–4.5 秒的短间隔转场抽帧，没有把画面中的产品介绍当成工作台需求，也未验证其产品功能。

目标是让工作台可重复制作同类科技产品讲解视频：统一视觉包装，内容随旁白逐步演示，支持卡片、连线、图表、光标、状态切换和章节移动。

## 参考片的组成

| 时间约值 | 画面表现 | 应提供的能力 |
| --- | --- | --- |
| 0–3.5 秒 | 聊天与学习系统对比，划线否定左侧、突出右侧，展开节点关系 | 对比布局、划线、聚焦、关系图 |
| 3.5–9 秒 | 文档卡片进入资料处理区域，进度增长，知识图谱与回答出现 | 路径移动、状态切换、数字增长、连线绘制、回答面板 |
| 9–11 秒 | 讲解卡片旁出现习题，选项变红或绿 | 双栏布局、答题状态、选择反馈 |
| 11–15 秒 | 三张功能卡依次聚焦，图表、滑块、阅读区变化 | 卡片聚焦、曲线绘制、参数驱动演示 |
| 15–17 秒 | 学习路径节点亮起并调整连接 | 路径描绘、节点状态、路径切换 |
| 17–23 秒 | 公式分步展示、对话气泡、波形、论文关系图 | 步骤列表、聊天面板、波形、关系图 |
| 23–29.37 秒 | 记忆层级与聊天渠道依次亮起，消息出现 | 层级列表、开关、标签切换、消息序列 |

画面还包括固定章节标题、蓝色强调线、章节序号、暗色背景装饰及底部青色字幕。可见光标在模块之间移动并引导注意力。仅凭成片不能确认这些画面来自真实录屏还是程序生成；工作台应同时支持两条制作路径。

## 当前基础与实际缺口

- `src/Video.tsx` 已有统一视频时钟、配音、字幕、场景入场和五种图解。
- `src/PaperStyle.tsx` 已有顺序入场和轻微回弹，可以提炼成通用动效。
- `src/EditorialVisual.tsx` 已有专用演示，但内容和部分时间点绑定了之前的 SolidWorks 视频，不能直接当作通用组件库。
- `src/model.ts` 的场景主要是标题、字符串数组和一个角色；已有 `visual.events` 只提供时间和标签，不能表达多个独立对象及其连续状态。
- `core/project.mjs` 当前工程版本为 1，校验和规则草稿都围绕五类场景。
- `src/App.tsx` 的素材页目前只显示角色目录，时间轴也没有元素事件编辑能力。
- `server.mjs` 的 MP4 导入走音轨流程，只保留音频用途；这不等于支持录屏作为画面图层。

因此需要同时改造场景数据、渲染器、编辑器和资产管理。

## 推荐架构

保留当前本地服务、Remotion、配音主时钟、版本检查及渲染队列。增加以下四层：

1. 视觉主题：统一背景、字体、边框、强调色、章节信息与字幕安全区。
2. 可配置组件：卡片、列表、聊天、关系图、曲线、进度、步骤、媒体画面。
3. 演示事件：描述某时刻哪个组件进入、激活、连线、更新数值或显示内容。
4. 场景模板：把组件和演示事件组装成可复用布局，供用户或 Agent 填写。

一般素材、可编辑组件和动效预设分别登记，统一在素材界面中选择。动效预设应包含名称、标签、适用对象、默认参数、动态预览和可调整项，而不仅是磁盘里的视频文件。

### 场景数据约定

建议引入版本 2，设计阶段先确定结构，再实现迁移。现有版本 1 的工程继续可读；迁移显式执行并保留原工程，避免静默破坏历史项目。

- 每个组件使用稳定 ID 和受支持的组件类型；业务文案与布局参数分离。
- 每个事件使用稳定 ID、组件目标 ID、相对场景起点的秒数、持续时间和参数。
- 连线绑定节点 ID；光标、圈注和聚焦绑定组件 ID 或其命名锚点，减少布局调整导致的错位。
- 定义常用命名锚点，例如卡片中心、按钮中心、节点中心；允许局部偏移。
- 支持事件与字幕 ID 关联及时间偏移；改字幕时间后可重新计算联动时间。
- 组件可定义状态，例如 idle、active、success、error；视觉由主题统一控制。
- 所有预览和导出由视频帧求值；拖到任意时刻直接得到相同结果，不依赖之前是否播放。
- 校验目标存在、时间有效、参数范围及不兼容的并发事件；同一属性冲突时采用明确且稳定的优先规则。
- 普通工程只引用已登记的组件与媒体，不执行上传文件中的任意代码。

### 首批动效预设

1. 淡入并上移。
2. 按顺序出现。
3. 卡片聚焦并压暗其他卡片。
4. 边框或节点脉冲。
5. 连线与路径逐段绘制。
6. 数字与进度增长。
7. 光标移动及点击波纹。
8. 文档或卡片沿路径移动。
9. 内容或文字分段显示。
10. 正确、错误及完成状态反馈。
11. 划线、下划线或圈注强调。
12. 章节横向滑动与推镜。

场景内部的摄像机变换只影响内容层；章节信息和字幕保持独立。真正的场景推移需在过渡期间同时渲染前后场景，不能仅让新场景向上进入。

## 实施顺序与验收

### 第一阶段：先做可评审的 8–10 秒样片

以参考片 3.5–9 秒的知识库片段为目标，制作一个独立演示工程，使用自己的示例数据与中性内容。

交付范围：

- 深色科技主题与章节标题。
- 资料卡片、处理面板、知识关系图、回答卡四类组件。
- 卡片移动、进度增长、节点连线、光标移动、聚焦及字幕联动。
- 场景事件的最小数据结构和校验。
- 通过现有导出流程生成一条真实的 1080p 样片。

建议样片节奏：

| 相对时间 | 演示事件 |
| --- | --- |
| 0–1.5 秒 | 三份资料依次出现，第一份资料沿路径进入处理区 |
| 1.5–3 秒 | 导入状态与进度更新，处理模块依次激活 |
| 3–5 秒 | 知识节点和连线依次出现，数量增长 |
| 5–7 秒 | 光标转向回答区，资料引用与回答内容出现 |
| 7–9 秒 | 关键结果聚焦，保留阅读时间并进入下一章节 |

先通过样片确认视觉密度、字号、节奏和动效幅度，再推广为通用库。

验收：任意跳转时间和连续播放状态一致；预览和导出一致；字幕不被遮挡；旧工程可以正常打开；样片包含真实导出文件。参考片部分小字在缩小观看时较密，新模板应支持简化信息、放大关键模块。

### 第二阶段：让演示能力可编辑、可复用

- 资产管理支持图片、GIF、视频和音频，保存稳定 ID、元数据及缩略图。
- 视频图层支持起止裁剪、画面裁切、播放速度、原声开关及静音默认值。
- 素材页增加组件、动效和场景模板的分类、搜索及动态预览。
- 时间轴增加组件与事件轨道，可调整起点、时长及事件目标。
- 属性面板支持文本、颜色、数值、状态、路径、关联字幕。
- CLI/API 增加目录查询和结构化参数说明，供 Agent 生成可校验的工程。
- 用户仍可导入真实录屏，叠加裁切、局部聚焦、光标与标注；演示画面和真实录屏在项目中明确区分。

### 第三阶段：完善同类视频的模板覆盖

增加系统关系图、知识入库、讲解与练习、三功能展示、成长路径、学科能力、记忆与渠道等场景模板。补充曲线、聊天、波形和公式组件，继续复用同一套事件机制。

自动编排应先使用字幕确定信息结构，再选模板并安排演示事件。现有规则草稿只能作为起点，不能仅靠关键词和换肤生成参考片的叙事质量。

## 代码改动落点

| 文件或建议目录 | 改动 |
| --- | --- |
| `src/model.ts` | 场景组件、事件、媒体和主题的数据类型 |
| `core/project.mjs` | 工程迁移、结构校验、时间及目标引用校验 |
| `core/themes.mjs` | 增加科技风格主题，不替换已有标准与可爱主题 |
| `src/Video.tsx` | 连接通用场景渲染器与场景过渡 |
| 建议新增 `src/motion/` | 基于帧的事件求值、路径与预设 |
| 建议新增 `src/components/video/` | 可配置卡片、图谱、图表、光标等组件 |
| 建议新增 `src/scenes/` | 组件组合形成的模板 |
| `src/EditorialVisual.tsx` | 保留原视频，逐步提取无业务绑定的组件 |
| `src/App.tsx`、`src/app.css` | 组件选择、事件编辑、模板及动效预览 |
| `server.mjs`、`cli.mjs` | 媒体导入、目录接口与工程兼容 |

代码实施时执行仓库要求的 `npm run check` 与 `npm run build`；增加有意义的事件时钟、引用校验及旧工程兼容检查，渲染代表帧与样片做视觉验收。

## 实施状态

本文保留实施前的参考拆解与架构建议。当前已交付 20 项 AI 可调用动效，以及科技风格与六类连续演示效果，详见 [AI 动效资源包](motion-library.md) 和 [科技风格与演示效果](tech-style.md)。

当前仍使用兼容版本 1 的可选字段，没有实施本文建议的版本 2 通用元素时间轴、任意媒体图层或完整素材管理界面。本地验收样片由脚本生成，不随仓库上传用户素材和工程数据。
